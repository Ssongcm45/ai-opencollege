# 관리자 최초 설정 및 보안

## 최초 관리자 설정

1. Node.js에서 별도의 안전한 토큰을 생성합니다.

   ```sh
   node -e "console.log(require('node:crypto').randomBytes(32).toString('hex'))"
   ```

2. 배포 환경의 `ADMIN_SETUP_TOKEN`에 생성한 값을 설정하고 재배포합니다. 토큰은 32자 이상의 안전한 무작위 값이어야 합니다. `ADMIN_SESSION_SECRET`와 같은 값을 쓰지 마세요. 이 설정이 비어 있거나 없으면 최초 관리자 설정은 거부됩니다.
3. 관리자 최초 설정 폼에 `ADMIN_EMAIL`에 지정한 이메일, 비밀번호, 그리고 `ADMIN_SETUP_TOKEN` 값을 입력해 설정을 완료합니다.
4. 설정에 성공하면 배포 환경에서 `ADMIN_SETUP_TOKEN`을 제거하고 다시 배포하는 것을 권장합니다. 런타임 환경 변수 변경은 재배포해야 적용됩니다. 이미 설정된 관리자 계정은 토큰 제거의 영향을 받지 않습니다.

토큰을 URL, 소스 코드, 로그 또는 공유 채널에 넣지 마세요. 필요한 배포 담당자만 안전한 비밀 저장소에서 전달받아야 합니다.

## 로그인 및 데이터베이스 오류

세션 검증은 데이터베이스 버전 확인이 실패하거나 데이터베이스 설정이 없으면 거부됩니다. 관리자 업로드도 같은 검증을 적용합니다. 데이터베이스 오류가 나면 재로그인을 반복하지 말고 먼저 데이터베이스 연결과 상태를 복구하세요.

이번 변경에는 운영 데이터베이스 마이그레이션이 없습니다. 등록된 관리자 이메일과 다른 이메일의 로그인 요청은 전역 실패 횟수에 반영하지 않습니다. 관리자 이메일을 아는 공격자에 대한 전역 잠금 정책 개선과 공개 이메일 엔드포인트의 호출 제한은 후속 작업으로 남아 있습니다.

## 검증

- `npm run test:auth`: 실제 인증 함수와 서버 액션을 호출하는 회귀 테스트입니다. 요청·DB·업로드 경계는 대체하며, 운영 DB와 외부 발송 서비스에 연결하지 않습니다. Drizzle이 생성하는 조건부 SQL과 경쟁 요청에서 영향받은 행이 없는 경우를 검증합니다. 실제 PostgreSQL에서 동시 요청을 실행하는 통합 테스트는 아닙니다.
- `npm run typecheck`: TypeScript 정적 검사입니다.
