# 교육 문의 분석 운영 안내

문의 분석은 접수 내용을 내부 담당자가 검토할 수 있도록 요약하고, 교육 목표를 중심으로 과정과 진행 방식, 추가 확인 항목을 제안합니다. 결과와 고객 회신 초안은 관리자 화면에 표시되며, AI 추천은 확정 견적이나 고객 발송 답변이 아닙니다.

## 분석 기준

분석은 문의에 적힌 교육 목표를 가장 중요한 기준으로 삼습니다. 목표가 입력되어 있으면 원문을 그대로 보존하고, 다른 문의 내용에서 추정한 목표와 구분합니다. 확인된 사실에는 문의 원문에 실제로 포함된 근거가 있어야 하며, 일정·인원·장소·가격·첨부·합의 사항을 추측하지 않습니다. 문의에 포함된 지시문은 분석 지침으로 취급하지 않습니다.

추천 과정은 다음 세 과정 안에서 최대 세 개까지 제안합니다.

- 생성형 AI 기초과정: 2~3시간, 생성형 AI와 프롬프트를 처음 사용하는 학습자
- AI 활용 기초과정: 3~4시간, LLM 사용 경험이 있는 학습자의 프롬프트와 모델 이해
- 실무적용 AI 일반과정: 4시간, 코딩·보고서·통계·오픈소스·한글 문서 실습

강의형은 주강사 1명, 실습형은 주강사 1명과 보조강사 1~2명으로 제안합니다. 모둠실습형일 때만 보조강사 1명당 참여자 최대 6명 기준을 적용합니다. 유료 AI 계정이 없으면 Gadia AIMS를 선택 가능한 대안으로 검토합니다. 실제 과정 구성과 시간, 견적은 목표와 운영 조건을 담당자가 확인한 뒤 정합니다.

## 접수와 알림

Vercel의 문의 분석에는 `OPENROUTER_API_KEY`가 필요합니다. 로컬 개발은 로그인된 Codex CLI를 기본으로 사용하므로 API 키가 필요하지 않습니다. `INQUIRY_AI_MODEL`을 설정하면 OpenRouter 모델을 지정하며, 비워 두면 `OPENROUTER_MODEL`, 다시 비어 있으면 `google/gemini-2.5-flash`를 사용합니다. 분석 결과는 정해진 JSON 구조로 검증한 뒤 저장합니다.

접수 알림 메일은 관리자 주소로 전송되고, 문의자의 이메일은 회신 주소로 지정됩니다. `RESEND_API_KEY`가 필요하며 발신 주소는 `RESEND_FROM`으로 지정할 수 있습니다. 설정하지 않으면 `AI OpenCollege <edu@opencollege.co.kr>`을 사용합니다. 메일에는 문의 원문, 분석 결과 또는 분석 실패 안내, 관리자 문의 링크가 포함됩니다. AI가 문의자에게 메일을 직접 보내지는 않습니다.

## 실패 확인과 수동 재처리

관리자 문의 화면에서 분석 및 알림 상태를 확인합니다. 분석 또는 알림에 실패한 문의는 관리자 인증 후 재처리를 요청할 수 있습니다. 처리 작업은 접수 요청 뒤 `after()`에서 실행되므로, 이는 요청 수명 안에서 후속 작업을 수행하는 방식이며 영구 큐나 예약된 자동 복구 작업은 아닙니다. 프로세스 중단 등으로 작업이 끝나지 않았다면 상태를 확인한 뒤 관리자가 재처리해야 합니다.

알림 상태가 `uncertain`이면 Resend에서 해당 발송 여부를 확인하고 중복 발송 위험을 해소한 뒤 처리합니다. 이 상태는 자동 재시도하지 않으며 관리자 재처리 동작도 차단합니다. `sending` 상태에서 공급자 응답을 받기 전에 실패한 경우도 중복 방지를 위해 불확실 상태로 남을 수 있습니다. 먼저 공급자 기록을 확인하세요.

고객 답변 초안은 관리자가 화면에서 수정하고 복사하거나 메일 앱에서 열 수 있습니다. 전송 전에 내용을 확인하고 직접 발송합니다. 화면에서 수정한 내용은 저장되지 않습니다.

## 기존 문의와 DB 변경

기존 문의는 자동으로 분석 대상으로 바뀌지 않습니다. 운영자가 관리자 화면에서 분석과 알림을 명시적으로 시작한 문의만 처리됩니다. 운영 DB 연결값(`DATABASE_URL`)을 사용하는 경우 관리자 화면 사전 렌더링이 새 열을 조회하므로, 빌드와 배포 전에 `migrations/0013_inquiry_analysis.sql`을 기존 Neon 데이터베이스에 먼저 적용하세요. 이 파일은 기존 문의 테이블에 분석·처리 필드를 추가하고 중복 접수 및 요청 제한용 구조를 만듭니다. 기존 데이터 행을 초기화하거나 다시 만들지 않습니다.

이 프로젝트의 수동 마이그레이션 파일을 지정해 적용해야 합니다. `db:push`를 사용하지 말고, Drizzle의 기본 `db:migrate`도 이 `migrations/` 파일을 적용하는 명령이 아니므로 사용하지 마세요. 적용 후 읽기 전용 DB 점검으로 필수 테이블과 열이 있는지 확인하고 애플리케이션을 배포합니다.

## 로컬에서 기존 문의 다시 분석하기

로그인된 Codex CLI를 기본으로 쓰므로 로컬에서는 API 키를 설정하지 않아도 됩니다. 서버는 다음처럼 실행합니다.

```sh
npm run dev -- --hostname 127.0.0.1
```

Claude CLI로 바꾸려면 `.env.local`에 `INQUIRY_AI_PROVIDER=claude`를 설정합니다. 기본값은 `codex`입니다. Vercel에서는 이 설정과 관계없이 항상 OpenRouter를 사용합니다.

로컬에서 관리자 계정으로 로그인한 뒤 기존 문의의 재분석을 명시적으로 누르면 로컬 서버가 연결된 DB의 해당 문의를 처리합니다. 재분석은 기존 데이터에 분석 결과를 저장하며, 알림 메일이 전송될 수 있습니다. 관리자 화면에서 동작을 누르지 않으면 재분석하지 않습니다. 로컬 서버를 켜 두는 것만으로 운영 문의를 자동 조회하거나 처리하지 않습니다.

- Next.js [`after()`](https://nextjs.org/docs/app/api-reference/functions/after)는 요청 처리와 연계해 후속 작업을 실행합니다. 내구성 있는 작업 큐를 제공하지 않습니다.
- Resend [이메일 멱등성 키](https://resend.com/docs/dashboard/emails/idempotency-keys)는 같은 요청의 중복 발송을 줄이는 데 사용됩니다. 불확실한 상태에서는 공급자 기록을 확인하세요.
- OpenRouter [구조화된 출력](https://openrouter.ai/docs/guides/features/structured-outputs)은 분석 응답의 JSON 형식을 제한하는 데 사용됩니다.
