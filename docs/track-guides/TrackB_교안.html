Claude API 개요 — REST vs SDK, 인증, 요금제
15분

Claude API는 HTTP REST API이지만 대부분은 Anthropic 공식 SDK를 사용합니다. Python과 TypeScript/JavaScript SDK가 공식 지원됩니다.

항목내용비고

인증x-api-key: sk-ant-... 헤더절대 코드에 하드코딩 금지
모델claude-sonnet-4, claude-haiku-4-5 등용도별 선택

우선순위 계층
Anthropic 정책 ← Claude 학습 단계에서 적용, 최상위 ↓ System Prompt ← 개발자가 정의하는 제약과 역할 ↓ User Message ← 실제 사용자의 요청 ↓ Assistant Prefill ← 응답 시작점 제어 (고급)
파라미터범위용도권장값
temperature0.0–1.0창의성 제어분석: 0.1 / 창작: 0.7–0.9
top_p0.0–1.0어휘 다양성일반: 1.0 (건드리지 않음)
top_k정수후보 토큰 수기본값 사용 권장
max_tokens정수최대 출력 제한예상 출력 × 1.5
temperature 선택 가이드
0.0–0.3: 분류, 구조화 추출, 코드 생성 — 일관된 답이 필요할 때
0.5–0.7: 요약, 번역, 보고서 — 균형이 필요할 때
0.8–1.0: 카피라이팅, 브레인스토밍 — 다양한 시도가 필요할 때

구조화된 출력 — XML 태그와 JSON 파싱
20분

프로덕션 앱에서 Claude 응답을 그대로 사용자에게 보여주는 경우는 드뭅니다. 대부분 파싱해서 데이터로 처리해야 합니다. Claude는 XML 태그를 잘 따릅니다.

❌ 파싱하기 어려운 응답

시스템에 "감정을 분석해줘"라고 요청
→ "이 텍스트는 약간 부정적인 감정이 담겨있으며 긴장감도 느껴집니다..." (비구조적)

✓ 파싱 가능한 구조화 응답

XML 또는 JSON 형식 요청
→ <sentiment>negative</sentiment><confidence>0.82</confidence>

코드 실습
시스템 프롬프트 + 구조화 출력
python
import anthropic import json import re client = anthropic.Anthropic() # 시스템 프롬프트: Claude의 역할과 출력 형식을 정의 SYSTEM_PROMPT = """ 당신은 전문 감성 분석가입니다. [규칙] - 항상 아래 XML 형식으로만 응답하세요 - 감성 레이블: positive / negative / neutral - confidence는 0.0~1.0 사이 소수점 2자리 - 추가 설명 없이 XML만 출력 [출력 형식] 레이블 0.00 핵심 감성 키워드들 """ def analyze_sentiment(text: str) -> dict: response = client.messages.create( model="claude-haiku-4-5-20251001", # 분류는 Haiku로 (비용 절약) max_tokens=256, temperature=0.0, # 일관성을 위해 0 system=SYSTEM_PROMPT, # 시스템 프롬프트 전달 messages=[{"role": "user", "content": text}] ) # XML 파싱 xml = response.content[0].text return { "sentiment": re.search(r'<sentiment>(.+?)</sentiment>', xml).group(1), "confidence": float(re.search(r'<confidence>(.+?)</confidence>', xml).group(1)), "keywords": re.search(r'<keywords>(.+?)</keywords>', xml).group(1) } # 테스트 result = analyze_sentiment("이 제품 정말 최악이에요. 환불하고 싶어요.") print(result) # → {'sentiment': 'negative', 'confidence': 0.95, 'keywords': '최악, 환불'}

멀티턴 대화 구조
요청 1: messages = [ {"role": "user", "content": "파이썬 배우고 싶어"} ] 요청 2: messages = [ {"role": "user", "content": "파이썬 배우고 싶어"}, {"role": "assistant", "content": "좋아요! 먼저..."}, ← 이전 응답 추가 {"role": "user", "content": "변수부터 알려줘"} ] 요청 N: messages = [이전 모든 대화 + 새 메시지] ← 대화가 길어질수록 비용↑, 속도↓
컨텍스트 윈도우 관리 전략
슬라이딩 윈도우: 최근 N개 메시지만 유지
요약 압축: 오래된 대화를 요약해 하나의 메시지로 압축
선택적 포함: 현재 질문과 관련 있는 대화만 포함

from typing import List, Dict import anthropic class ConversationManager: """대화 이력을 관리하는 클래스""" def __init__(self, system_prompt: str, max_turns: int = 10): self.client = anthropic.Anthropic() self.system = system_prompt self.max_turns = max_turns self.history: List[Dict] = [] def chat(self, user_message: str) -> str: # 사용자 메시지 추가 self.history.append({ "role": "user", "content": user_message }) # 슬라이딩 윈도우: 최근 N 턴만 유지 trimmed = self.history[-self.max_turns * 2:] response = self.client.messages.create( model="claude-sonnet-4-20250514", max_tokens=2048, system=self.system, messages=trimmed ) assistant_reply = response.content[0].text # 응답 이력에 추가 self.history.append({ "role": "assistant", "content": assistant_reply }) return assistant_reply def summarize_and_reset(self) -> str: """대화가 너무 길어지면 요약 후 압축""" summary_prompt = f""" 다음 대화를 3줄로 핵심만 요약해줘: {str(self.history)} """ summary = self.client.messages.create( model="claude-haiku-4-5-20251001", max_tokens=256, messages=[{"role": "user", "content": summary_prompt}] ).content[0].text # 요약으로 이력 초기화 self.history = [{ "role": "user", "content": f"[이전 대화 요약] {summary}" }, {"role": "assistant", "content": "이전 대화 내용을 기억하고 있습니다."}] return summary # 사용 예시 bot = ConversationManager("당신은 친절한 AI 어시스턴트입니다.", max_turns=5) print(bot.chat("파이썬 배우고 싶어")) print(bot.chat("변수부터 알려줘")) # 이전 맥락 유지됨

import anthropic import json from datetime import datetime client = anthropic.Anthropic() # 1. 도구 정의 (JSON Schema) TOOLS = [ { "name": "get_current_weather", "description": "현재 도시의 날씨를 가져옵니다", "input_schema": { "type": "object", "properties": { "city": {"type": "string", "description": "도시명 (예: 서울, 부산)"} }, "required": ["city"] } }, { "name": "calculate", "description": "수식을 계산합니다", "input_schema": { "type": "object", "properties": { "expression": {"type": "string", "description": "파이썬 수식 (예: 2**10)"} }, "required": ["expression"] } } ] # 2. 실제 함수 구현 def get_current_weather(city: str) -> dict: # 실제로는 날씨 API 호출 return {"city": city, "temp": 22, "condition": "맑음"} def calculate(expression: str) -> dict: try: result = eval(expression) # 실제 환경에선 sandboxing 필요! return {"result": result} except: return {"error": "계산 실패"} # 3. 에이전트 루프 def run_agent(user_message: str) -> str: messages = [{"role": "user", "content": user_message}] while True: response = client.messages.create( model="claude-sonnet-4-20250514", max_tokens=4096, tools=TOOLS, messages=messages ) # 완료되면 리턴 if response.stop_reason == "end_turn": return response.content[0].text # tool_use 처리 tool_results = [] for block in response.content: if block.type == "tool_use": print(f"🔧 도구 호출: {block.name}({block.input})") # 도구명에 따라 함수 실행 if block.name == "get_current_weather": result = get_current_weather(**block.input) elif block.name == "calculate": result = calculate(**block.input) tool_results.append({ "type": "tool_result", "tool_use_id": block.id, "content": json.dumps(result, ensure_ascii=False) }) # 도구 결과를 메시지에 추가하고 반복 messages.append({"role": "assistant", "content": response.content}) messages.append({"role": "user", "content": tool_results}) # 테스트 print(run_agent("서울 날씨 알려주고, 2의 10승도 계산해줘")) # Claude가 두 도구를 모두 자동 선택해서 호출

MCP(Model Context Protocol)는 Anthropic이 설계한 오픈 표준 프로토콜입니다. AI 앱(Host)이 다양한 데이터 소스 및 도구(Server)와 통신하는 방식을 표준화합니다.

MCP 아키텍처 삼각형
Host (Claude Desktop, Claude.ai, 커스텀 앱) ├── MCP Client 1 ←→ MCP Server A (파일시스템) ├── MCP Client 2 ←→ MCP Server B (GitHub) └── MCP Client 3 ←→ MCP Server C (내가 만든 서버) # 각 역할 Host : Claude를 실행하는 환경 (Claude Desktop 등) Client : Host 내부에서 Server와 통신하는 컴포넌트 Server : 도구·데이터·기능을 제공하는 경량 프로세스
MCP 원시 타입역할예시
Resources데이터/파일 노출파일 내용, DB 레코드, API 응답

Prompts재사용 가능한 프롬프트 템플릿코드 리뷰 프롬프트, 번역 프롬프트
MCP vs 기존 Tool Use 차이
기존 Tool Use: 개발자가 직접 함수 정의 → Claude API에 전달 → 결과 처리 (앱 내부에서 모두 처리)
